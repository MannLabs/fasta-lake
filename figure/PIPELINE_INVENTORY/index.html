    FastaLake pipeline inventory and final figure audit#

    Scope: the default manifest-runner workflow. Readable definitions take priority over implementation labels. The current MannLabs executable code determines behavior; the current v11 manuscript supplies the terminology cross-check. No older figure was used as evidence.

    Source identity and audit boundary#

    • Repository: MannLabs/fasta-lake, default branch main, observed live through git ls-remote --symref on 23 September 2026.
    • Audited commit: e072ca2a9b73dcd16f85ebc73bec9f2d9f9e2773 (22 September 2026, “Organize repository support files by purpose (#59)”). An isolated clean clone was inspected; the much larger local manuscript repository and another window's edited checkout were not used as software authority.
    • Package version: 1.1.0rc2. fasta_lake/init.py::version L13–13
    • Manuscript terminology was checked against the v11 review package dated 23 September 2026 (DOCX SHA-256 aaeccb7b9efe589e0187b0a992ce449d28464d56b1af71ac71fa4f0cd8bb1ccd). The twelve audited Methods paragraphs match the earlier integrated v11. This checks terminology; scientific Methods review remains separate. Manuscript files and private coordination records are not distributed with the figure.
    • This is static execution-path inspection, not a new proteomics run, performance benchmark or independent error-calibration study.

    Meaning of scope: “study-level” means once for the declared acquisition roster; “sample-level” means once per mass-spectrometry acquisition (one manifest row), not necessarily once per biological specimen. Use “For the study” and “For each acquisition”, with “acquisition = one MS run” in the figure.     Entry points and actual orchestration#

    The primary end-to-end route is python tools/run_manifest.py --manifest … --lake … --out …. It starts with an existing protein FASTA, prediction CSVs and mzML files. It has no JSON pipeline-config argument. Its argument defaults and generated fasta_lake.search.sage_config() control the route below. The installed fasta-lake command instead dispatches individual Click commands. tools/run_manifest.py::main L99–183

    Actual call path, in execution order:

    tools/run_manifest.py::main
  load_manifest; validate arguments, binaries and dependencies
  create provenance and pooled prediction-file links
  extract("evidence", lake, pooled_predictions, evidence.fasta)
    fasta_extractor: filter each CSV, pool queries, exact lookup
  for each manifest row:
    extract("<sample>_extract", evidence.fasta, that CSV, sample_lake.fasta)
    execute("<sample>_infer", parsimony_engine --strategy razor --tiebreak hash-acc)
    [molecular add, only when a specimen-qualified source is supplied]
    sage_config → execute("<sample>_search", Sage 0.14.6 --write-pin)
  execute("aggregate", aggregation_engine)
  execute("study_quantification", tools/group_study.py --quantification sum)
    study.group_searches → study_dictionary → _quantify
    quantification.quantify_study(method="sum")
    downstream.analyze_study [unless --skip-qc]
  [annotate study, only with --annotation-settings]
  COMPLETE.json

    The per-acquisition loop completes extraction, selection and search for one row before the next. aggregate executes before study grouping, but its matrices are not inputs to the study dictionary: both independently read search/.     Exact eligibility definition behind the short labels#

    The lookup filter removes a prediction when any residue exceeds 60% of its sequence, when a sequence of at least 12 residues has at most 2 residue types, or when a sequence of at least 10 residues is an alternating two-residue repeat. Complexity is checked before I/L normalization. The top-30% rule applies to eligible rows, includes cutoff ties, and is followed by unique-sequence pooling. A short figure label can say “Filtered de novo predictions”; detailed rules belong here or in HTML hover text. rust/fasta_extractor_v2/src/main.rs::normalize_il_seq / is_low_complexity L305–347
    rust/fasta_extractor_v2/src/main.rs::load_peptides_top_percent L408–465
    rust/fasta_extractor_v2/src/main.rs::load_peptides_top_percent_single_csv L568–620

    Selection parsimony ranks fixed evidence counts; it does not repeatedly recompute uncovered peptide gains. Post-search study grouping does recompute uncovered gains. Both can reduce a protein representation, but they act on different evidence at different times. Do not collapse them into one “protein inference” box. rust/parsimony_engine/src/main.rs::run_razor L783–895

    Figure scope#

    The figure uses these boundaries:

    1. Begin with the prepared protein reservoir, supplied prediction CSVs and measured mzML spectra. Reservoir construction, conversion and model inference are upstream inputs.
    2. Show the default route through summed group intensities and QC. Optional directLFQ, molecular additions and representative annotation appear only in the HTML notes.
    3. Show the auxiliary search-summary tables as a branch from search results. Combine D6/D7 into “Study groups and intensities”; the primary study matrix does not consume the auxiliary summaries.

    The design uses study lookup → each acquisition → study results, with one accent colour for each group. All eligible predictions enter selection separately from the filtered lookup queries. The code provenance and reproducible assets are included alongside this inventory.
