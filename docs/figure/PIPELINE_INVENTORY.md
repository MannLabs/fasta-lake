## Entry points and actual orchestration

The primary end-to-end route is `python tools/run_manifest.py --manifest … --lake … --out …`. It starts with an existing protein FASTA, prediction CSVs and mzML files. It has no JSON pipeline-config argument. Its argument defaults and generated `fasta_lake.search.sage_config()` control the route below. The installed `fasta-lake` command instead dispatches individual Click commands. [tools/run_manifest.py::main L99–183](https://github.com/MannLabs/fasta-lake/blob/e072ca2a9b73dcd16f85ebc73bec9f2d9f9e2773/tools/run_manifest.py#L99-L183)<br>[tools/run_manifest.py::load_manifest L40–96](https://github.com/MannLabs/fasta-lake/blob/e072ca2a9b73dcd16f85ebc73bec9f2d9f9e2773/tools/run_manifest.py#L40-L96)<br>[pyproject.toml::[project.scripts] L48–49](https://github.com/MannLabs/fasta-lake/blob/e072ca2a9b73dcd16f85ebc73bec9f2d9f9e2773/pyproject.toml#L48-L49)<br>[fasta_lake/search.py::sage_config L60–108](https://github.com/MannLabs/fasta-lake/blob/e072ca2a9b73dcd16f85ebc73bec9f2d9f9e2773/fasta_lake/search.py#L60-L108)

Actual call path, in execution order:

```text
tools/run_manifest.py::main
  load_manifest; validate arguments, binaries and dependencies
  create provenance and pooled prediction-file links
  extract("evidence", lake, pooled_predictions, evidence.fasta)
    fasta_extractor: filter each CSV, pool queries, exact lookup
  for each manifest row:
    extract("<sample>_extract", evidence.fasta, that CSV, sample_lake.fasta)
    execute("<sample>_infer", parsimony_engine --strategy razor --tiebreak hash-acc)
    [molecular add, only when a specimen-qualified source is supplied]
    sage_config → execute("<sample>_search", Sage 0.14.6 --write-pin)
  execute("aggregate", aggregation_engine)
  execute("study_quantification", tools/group_study.py --quantification sum)
    study.group_searches → study_dictionary → _quantify
    quantification.quantify_study(method="sum")
    downstream.analyze_study [unless --skip-qc]
  [annotate study, only with --annotation-settings]
  COMPLETE.json
```

The per-acquisition loop completes extraction, selection and search for one row before the next. `aggregate` executes before study grouping, but its matrices are **not inputs to the study dictionary**: both independently read `search/`. This is a branch in data flow, even though it is sequential in execution. ### Exact eligibility definition behind the short labels

The lookup filter removes a prediction when any residue exceeds 60% of its sequence, when a sequence of at least 12 residues has at most 2 residue types, or when a sequence of at least 10 residues is an alternating two-residue repeat. A short figure label can say **“Filtered de novo predictions”**; detailed rules belong here or in HTML hover text. ## Figure scope

The figure uses these boundaries:

1. Begin with the prepared protein reservoir, supplied prediction CSVs and measured mzML spectra. Reservoir construction, conversion and model inference are upstream inputs.
2. Show the default route through summed group intensities and QC. Optional directLFQ, molecular additions and representative annotation appear only in the HTML notes.
3. Show the auxiliary search-summary tables as a branch from search results. Combine D6/D7 into “Study groups and intensities”; the primary study matrix does not consume the auxiliary summaries.

The design uses **study lookup → each acquisition → study results**, with one accent colour for each group. All eligible predictions enter selection separately from the filtered lookup queries. The code provenance and reproducible assets are included alongside this inventory.
